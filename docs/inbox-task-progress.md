# 通知列表里的任务进度 · 设计

高保真稿：[design/inbox-task-progress/index.html](./design/inbox-task-progress/index.html) · 截图：`mockup-zh.png`
配套计划：[inbox-task-progress-plan.md](./inbox-task-progress-plan.md)
基线：`1.4.18`（通知面板 = 需要你处理置顶 + 今天/更早的通知行）

## 1. 现状的问题

1. **运行中不可见**：面板只收「收尾」事件。任务正在跑的时候打开铃铛，只能看到历史结果（或空态），「有活在跑」这件事在面板里不存在。
2. **分组丢失**：看板里父会话 + 子代理是一棵树（`3 个子代理 · 1 运行 · 2 完成`）；到面板只剩一行标题，看不出这次执行分出去多少活、各自到哪一步了。
3. **状态断层**：看板有四种状态（等待回复 / 运行中 / 未读结果 / 已读），面板只有等待回复、结果、已读三种，唯一的缺口正好是最需要「进度感」的那一种。

## 2. 目标与非目标

目标：

- 打开铃铛就能看到**运行中的任务**：标题、已运行时长、流动进度条，按父会话分组展示子代理。
- 运行中行**混进「今天」**，不新增区块头；它排在今天通知行的前面。
- 结果行带上**分组规模**（`3 个子代理`），一眼知道这次运行是单线程还是派了活。
- 保持一列竖排的列表形态，不把看板的三列搬进面板。

非目标：

- 不编造百分比进度（没有真实进度数据，只给已运行时长 + 不确定流动条）。
- 不在面板里新增子代理的**结果**通知（子代理结果仍只在看板里；面板按父会话汇总一条）。
- 不做折叠/展开交互，不改看板，不改宿主接口与发布契约。

## 3. 方案

「今天」区块里混入运行中任务：不新增区块头，运行中行排在最前，其余通知行按时间倒序跟在后面；「更早」仍是历史通知。等待回复的任务保持置顶在「需要你处理」。

```
┌ 通知                                   全部已读   × ┐
│ 全部   未读 3   待处理 1                     ⌄    │
├───────────────────────────────────────────────────┤
│ ● 需要你处理                                       │  ← 已有
│ ▌ 确认是否覆盖线上数据                    5 分钟前  │
│   等待审批                                          │
├───────────────────────────────────────────────────┤
│ 今天                                               │  ← 运行中行混在这里
│ ▌ 插件与工作区顺序调整                 已运行 12 分钟 │
│   任务 · 3 个子代理 · 1 运行                        │
│   ▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁ 流动条                        │
│    ├ 审查通知中心合并策略             已运行 6 分钟  │
│    ├ 支持编辑子任务改进                       完成   │
│    └ 番茄时钟添加嘀嗒音效                     完成   │
│ ▌ Mnemon idle checkpoint review       已运行 3 分钟 │
│   任务                                              │
│ ▌ 右上角全局通知中心设计                8 分钟前    │
│   任务 · 完成 5 次 · 3 个子代理                     │
│ ▌ 工作区与插件排序                      20 分钟前   │
│   任务 · 完成 1 次                                  │
├───────────────────────────────────────────────────┤
│ 更早                                               │
│ ▌ 初始化项目脚手架与代码规范检查         4 小时前   │
│   任务 · 完成 1 次                                  │
└───────────────────────────────────────────────────┘
```

三句话概括：

- **不加区块**：运行中行就是「今天」的前几行，蓝色色条 + `已运行` + 流动条把它和结果行区分开。
- **分组只在两个地方**出现：运行中的父行（展开子代理行）、结果行的副行（`N 个子代理`）。
- **状态用颜色表达**，行结构、未读点、字重、筛选口径全部沿用现有规则；运行中不计未读。

## 4. 行结构

### 4.1 运行中 · 根行

```
▌ 插件与工作区顺序调整                    已运行 12 分钟
  任务 · 3 个子代理 · 1 运行
  ▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁
```

| 部位 | 规格 |
| --- | --- |
| 色条 | 复用 `.dtn-ni__tone`：`3×16`、圆角 2、`business` 蓝 |
| 标题 | `13.5px / 500`、`label-primary`、单行省略与现有通知行一致 |
| 右侧 | `已运行 {time}`（复用 `card.runningFor`），`11px`、`label-tertiary`、等宽数字 |
| 副行 | `任务`（tertiary）+ `3 个子代理` + `1 运行`；复用 `tree.children` / `tree.childStatsRunning`，与看板同一套词 |
| 流动条 | 复用看板 `.dtn-live`：高 3、圆角 2，轨道 `business` 14%，滑块 38% 宽、1.6s 无限循环；只出现在根行 |
| 内边距 | 与通知行一致 `10px 14px` |
| 未读点 | 不出现（运行中没有未读概念） |

### 4.2 运行中 · 子代理行

```
   ├ 审查通知中心合并策略                 已运行 6 分钟
   ├ 支持编辑子任务改进                         完成
   └ 番茄时钟添加嘀嗒音效                       完成
```

| 部位 | 规格 |
| --- | --- |
| 缩进 | 子代理容器左外边距 17（对齐父行色条中线），1px 竖向连接线 `border-l1`；每行一段 17px 肘线接到状态图标；触屏不依赖 hover |
| 状态图标 | 运行中：6px 蓝色圆点（`business`）；完成：11px 绿色对勾（`success`）；中断：11px 琥珀/红警示（`warn`/`error`） |
| 标题 | `12.5px / 500`、单行省略；父行标题 `13.5px` |
| 右侧 | 运行中 `已运行 {time}`；完成 `完成`；中断 `中断`（`10.5px`，等宽数字） |
| 行高 / 缩进 | 行高 26；标题相对面板左边距 34（容器缩进 17 + 内容 17） |
| 副行 | 无。子代理同属一个父会话，来源与分组已在父行说明 |

子代理行的状态只用图标 + 右侧文字，不再加色条：一个组里只允许父行的色条表达组状态。**等待回复的子代理不在这里重复**——它已经在「需要你处理」置顶，也不计入父行的 `N 个子代理` 与 `N 运行`。

### 4.3 结果行的分组标注

结果行副行在原有内容后追加 `· 3 个子代理`：

```
▌ 右上角全局通知中心设计                    8 分钟前
  任务 · 完成 5 次 · 3 个子代理
```

- 仅当该会话在当前任务表里仍有 `parentId === sessionId` 的子会话时追加；没有就不加。
- 顺序固定：来源 → 次数/正文 → 分组规模。
- 文案复用 `tree.children`，不新增「含」「共」之类的措辞。
- 子代理自己的结果不生成通知，因此这里只报规模，不展开。

### 4.4 位置与排序

| 规则 | 说明 |
| --- | --- |
| 归属 | 运行中行属于「今天」，不新增区块头 |
| 顺序 | 运行中根组按 `changeAt` 倒序排在「今天」最前；随后是今天的通知行（`ts` 倒序） |
| 子行 | 组内运行中优先、再按 `changeAt` 倒序 |
| 空态 | 既没有通知、也没有运行中任务时才显示「暂无通知」 |
| 「更早」 | 只放历史通知，不出现运行中行 |

## 5. 分组与上限

- 根行：`running && !needsInput` 的会话；父会话没在跑（空闲 / 已结束 / 正在等人）的子代理提升为根行，副行写 `来自 {父标题}`，复用 `tree.fromParent`。
- 子行：`parentId === root.id && !needsInput` 的会话；只展开一层，`depth ≥ 2` 不进入面板。
- 上限：根组最多 **3** 个，子行每组最多 **3** 行；超出各给一行 `还有 {n} 个运行中` / `还有 {n} 个`（带 chevron，整行可点，跳看板）。
- 结果行的分组规模是**读时计算**，任务表裁剪后自然消失；不写进通知。

## 6. 筛选、计数、铃铛

| 位置 | 规则 |
| --- | --- |
| 全部 | 需要你处理 + 今天（运行中行在前、通知行在后）+ 更早 |
| 未读 | 只有通知行（运行中行隐藏，运行中不计未读） |
| 待处理 | 保持现状：只含 `needsInput` 的会话（提问 / 审批 / 计划审阅） |
| 来源筛选 | 切到账号 / 插件时隐藏运行中行；任务与「全部来源」时显示 |
| 铃铛角标 | 不变：未读通知 + 等待处理。运行中不增加角标，避免「一直在响」的假信号 |
| 头部未读 chip | 不变 |

## 7. 交互

- 点根行 / 子行 → 打开对应会话并收起面板（沿用 `openEntry` 的跳转路径）。
- 运行中行没有「标为已读」按钮：没有可读的东西，鼠标悬停不出现对勾。
- `还有 N 个` 行 → 打开任务面板（`selectPanel(PANEL_ID)`，三列同屏，完整树都在）。
- 面板打开且存在运行中任务时，本地 1s 计时刷新「已运行」；面板关闭或没有运行中任务时停表。已读行的「X 分钟前」不需要跟着跳。
- 子代理行不做折叠，避免和「还有 N 个」冲突。

## 8. 文案

| key | zh | en |
| --- | --- | --- |
| `center.childDone` | 完成 | Done |
| `center.childInterrupted` | 中断 | Interrupted |
| `center.moreChildren` | 还有 {n} 个 | {n} more |
| `center.moreRunning` | 还有 {n} 个运行中 | {n} more running |

复用：`card.runningFor`（已运行 {time}）、`tree.children`（{n} 个子代理）、`tree.childStatsRunning`（{n} 运行）、`tree.fromParent`（来自 {name}）、`center.source.task`（任务）、`center.tasks`（打开任务面板）。

## 9. 深色、窄屏与无障碍

- 深色：全部用现有 token，流动条与色条取 `--dsw-alias-state-business-primary`，不写死颜色。
- 窄屏（<640px 全宽 sheet）：行结构与缩进不变；子行右侧状态文案保持可见，标题优先截断。
- 无障碍：根行、子行都是独立的 `<button>`（`role="button"` 的现有行结构），`aria-label` = `打开会话：{标题}（运行中，已运行 {time}）`；子行写 `打开会话：{标题}（子代理，已完成）`。
- `prefers-reduced-motion`：复用现有规则停掉流动条动画（滑块铺满、整体降到 45% 透明度）。

## 10. 数据与实现

无需改宿主：客户端 `state.tasks` 已经带 `running / startedAt / parentId / parentTitle / depth / unread / interrupted / needsInput`，`/wait?rev` 轮询会在状态变化时推下来。

- `lib/client.js`
  - 新增 `runningGroups(tasks)`：把任务表按父会话折成 `{root, children}`，只保留运行中的根，独立子代理提升为根；等待回复的子代理排除。
  - `NotificationCenterRoot`：`todayRows = [...runningRows, ...todayFeedRows]`，`更早` 只放 feed；空态包含运行中。
  - 结果行 `rowMeta`：接受子代理数，追加 `tree.children`。
  - CSS：`.dtn-nr`、`.dtn-nr__kids`、`.dtn-nr__kid`、`.dtn-nr__more`、`.dtn-nr__live`。
- 文案：`lib/client.js` 内嵌 zh / en 两套 key。
- 预览与截图：`preview/index.html` 的 `seedTasks()` 已经有父会话 + 2 个运行中子代理 + 1 个已完成的子代理，补 1 条独立运行任务即可出图；`scripts/screenshot.mjs` 复用 `center-*` 三张。
- 测试：`test/client-panel.test.js` 增加「运行中行在全部筛选出现、未读筛选隐藏」「父行带子代理计数与流动条」「子行缩进与三态」「无通知但有运行中时不显示空态」。

## 11. 边界

| 情况 | 表现 |
| --- | --- |
| 0 条通知 + 1 个运行中 | 只有「今天」区块与运行中行，不显示「暂无通知」空态 |
| 4 个以上运行中 | 3 组 + `还有 N 个运行中` |
| 父行正在运行、子代理已完成且未读 | 子行显示「完成」，不显示未读点；未读结果仍在看板里 |
| 父会话已结束、子代理还在跑 | 子代理提升为根行，副行 `来自 {父标题}` |
| 父会话等人（needsInput）且子代理在跑 | 父行在「需要你处理」；子代理提升为根行，标「来自」 |
| 子代理也在等人 | 不进组、不计入 `N 个子代理`；只出现在「需要你处理」 |
| 连接异常 | 顶部错误条沿用现状；运行中按最后一次快照显示，计时用本地时钟 |
| 子代理被裁剪（任务表上限） | 结果行不带分组标注；不显示错误 |
| 上一轮结果未读、同一会话又开跑 | 今天里两行（运行中行 + 历史结果行），点任意一行都进同一会话；未读口径不变 |

## 12. 验收

- 1 个运行中任务、0 条未读：打开面板能看到该任务、已运行时长、流动条；铃铛仍无角标。
- 父会话 + 3 个子代理（1 运行、2 完成）：父行副行「3 个子代理 · 1 运行」，3 条子行缩进，状态与右侧文案正确。
- 4 个子代理：只列 3 条，末尾「还有 1 个」可跳到看板。
- 父行与子代理全部结束后：运行中行消失，今天区出现 1 条结果行，副行「任务 · 完成 1 次 · 3 个子代理」。
- 「未读」筛选下不出现运行中；「待处理」仍只含等待回复/审批。
- 中英、深浅色、400 与 390 宽截图各一张，无重叠、无溢出。
- 面板打开时「已运行」每秒更新；关闭后 CPU 无持续计时。

## 14. 已确认决策

2026-11-27 与用户确认：

1. **混进「今天」**，不单独成区；运行中行排在今天通知行前。
2. **子代理默认展开前 3 个**；超出折成「还有 N 个 ›」，点击进任务面板看完整树。
3. **铃铛角标不统计运行中**。
