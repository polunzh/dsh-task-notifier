# 通知中心视觉改版：配色与降噪

高保真稿：[design/notification-center-v2/index.html](./design/notification-center-v2/index.html)
配套计划：[notification-center-visual-refresh-plan.md](./notification-center-visual-refresh-plan.md)
基线：`1.4.10`，截图取自 2026-11-25 16:50 的 400px 面板（@2x）。

> 迭代记录：1.4.13 曾用 28px 应用瓦片（插件自己的 icon）标识来源；1.4.14 把插件名放进副行；
> 1.4.15 按用户反馈去掉全部 Logo，恢复用颜色区分状态、用文字标识来源。

## 1. 现状的问题

同一份真实数据在旧面板里：

1. **重复条目占一半**：`右上角全局通知中心设计` 出现 5 次、`Mnemon idle checkpoint review` 出现 3 次。任务每完成一轮就写一条新通知（`task:<sessionId>:<completedAt>`），面板成了事件日志。
2. **一行五重信号**：左侧 3px 色条、未读圆点、整行浅蓝底、加粗标题、hover 的「打开 ›」。它们没有叠加新信息，只叠加注意力。
3. **来源只能读文字**：每行底部一颗「插件：dsh-todo」chip，单独占一行，把行高从 50 抬到 76，一屏只放得下 8 条。
4. **头部 4 个元素、三种权级**：铃铛+标题+未读 chip、任务面板、全部已读、关闭。
5. **来源筛选是原生 select**：视觉重量与分段控件相当，却是个很少用的筛选。

## 2. 目标

- 一屏看完当天的事件：同样 10 条事件，改版后 5 行装下。
- 状态用颜色表达，来源用文字说清；两者都不额外占行。
- 一个信号只说一件事：颜色只标状态，未读只靠浅底 + 字重。
- 不引入任何图标资源：插件不发素材也能正确显示。

## 3. 行结构

```
[3px 色条]  ● 标题 ....................................... 时间
              副行：发送方 · 正文 / 结果计数（始终有）
```

| 部位 | 规格 |
| --- | --- |
| 行内边距 | `10px 14px`，行间距用 1px 分隔线（左右各缩进 14） |
| 色条 | `3×16`，圆角 `2`，与标题基线对齐；只表达状态 |
| 标题 | `13.5px`；已读 `500`，未读 `600`，`label-primary` |
| 未读点 | `6px` 圆，`business`，在标题前 |
| 时间 | `11px`，`label-tertiary`，右对齐、等宽数字 |
| 副行 | `12px`，单行省略；**每行都以发送方开头**（`label-tertiary`）：`任务` / `账号公告` / `插件：dsh-todo`；正文用 `label-secondary`，中断原因用琥珀/红 |
| 分隔线 | `border-l1`，`left/right: 14px` |

状态色：

| 状态 | 颜色 |
| --- | --- |
| 任务完成 | `success` 绿 |
| 中断（退出 / 欠费） | `warn` 琥珀 |
| 中断（报错） | `error` 红 |
| 账号公告 | `business` 蓝 |
| 插件通知 | `label-tertiary` 中性灰 |

去掉：应用瓦片（Logo）、未读点叠在图标上、状态徽标、「打开 ›」链接。

### 3.1 合并重复的任务结果

任务通知的 id 从 `task:<sessionId>:<completedAt>` 改为 `task:<sessionId>:<completed|interrupted>`：

- 同一会话、同一种结果再次发生时，更新 `ts`、`count++`、重新标未读，**不新增行**；
- 状态翻转（完成→中断）落在另一条 id 上，两种结果各自保留最近一次；
- 行上表现：`count > 1` 时副行写「完成 5 次」/「中断 2 次」，单次不写；
- 未读计数按条目算：同一会话连续完成 5 次 = 1 条未读。

语义变化：未读单位从「事件」变成「会话结果」。三列看板仍按会话列任务，两者一致。

### 3.2 子代理与后台运行

两类「看起来像任务、其实不值得提醒」的会话单独处理：

- **子代理会话**（`parentSession` + `origin: subagent`，例如 Mnemon 的空闲巡检、AgentTeams 成员）**不发独立通知**：它属于父会话的一次执行，看板里仍按树展示；父会话收尾时才提醒一次。谱系先从 `api-session/added` / `session/event` 读，事件没带就在收尾的标题快照里补（快照返回完整会话头），所以程序化拉起的会话也能识别。
- **后台任务**（定时巡检、自动化流水线）每轮新起一个会话、标题相同：会话 id 去重不起作用，改为**按标题合并**——同一标题、同一种结果、24 小时内并进同一条，行上写「完成 N 次」，点开指向最近一次会话。读取旧 `notifications.json` 时也按同样规则折叠一次，升级后历史重复行不会留在面板里。
- 真正需要人介入的「等你回复 / 审批」不受影响：它们来自任务表的 `needsInput`，仍然置顶在「需要你处理」。

## 4. 来源标识：文字，不依赖图标

- 每一行的副行都以发送方开头，用与筛选一致的词：任务 → `任务`，账号 → `账号公告`，插件 → `插件：<sourceLabel>`（复用 `center.pluginPrefix`）；
- 插件没发 `sourceLabel` 时显示「插件」；
- 发送方后接正文 / 「完成 N 次」/ 中断原因；没有这些时副行只有发送方；
- 宿主不读取任何插件图标：`/task-notifier/api/sources` 与客户端图标缓存一并移除，面板不加载任何图片素材。

无障碍：行的 `aria-label` 是 `标题，插件：dsh-todo · 正文`，读屏与视觉一致。

## 5. 头部与筛选

- 头部只留三件：铃铛 + 「通知」+ 未读 chip；右侧「全部已读」和关闭。任务面板入口下移到底部整宽按钮。
- 分段控件：`全部 / 未读 / 待处理`，计数只在 `> 0` 时显示。
- 来源筛选：漏斗图标按钮 + 弹出菜单（全部来源 / 任务 / 账号 / 插件，选中项打勾），28px。

## 6. 深色与窄屏

- 深色：色条直接用状态色 token，未读点取 `business`；没有图片素材需要特殊处理。
- 窄屏（< 640px）：面板变全宽 sheet（沿用现有规则），行结构不变。

## 7. 文案

| key | zh | en |
| --- | --- | --- |
| `center.countCompleted` | 完成 {n} 次 | Completed {n}× |
| `center.countInterrupted` | 中断 {n} 次 | Interrupted {n}× |
| `center.sourceMenu` | 来源筛选 | Filter by source |

`center.pluginPrefix`（插件：{name}）用于行内来源文字与系统通知。

## 8. 不做

- 不改三列任务看板。
- 不做「展开合并条目」的二级列表——合并后的行点开就是会话。
- 不加载任何图标资源，不给通知契约加 `icon` 字段。

## 9. 验收

- 同一会话连续完成 5 次：面板 1 行，副行「完成 5 次」，铃铛未读 +1 而不是 +5。
- 插件通知副行以「插件：dsh-todo」开头；未发 `sourceLabel` 时显示「插件」。
- 完成行绿条、中断行琥珀/红条、账号行蓝条、插件行灰条，不出现任何 Logo 或图片请求。
- 640px 高的面板至少容纳 9 条单行结果。
- 深浅色、中英、400/390 窄屏截图各一张，更新 README 与 `docs/design/notification-center-v2/`。
