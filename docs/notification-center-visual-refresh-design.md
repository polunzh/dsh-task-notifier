# 通知中心视觉改版（v2）：应用图标与降噪

高保真稿：[design/notification-center-v2/index.html](./design/notification-center-v2/index.html)
配套计划：[notification-center-visual-refresh-plan.md](./notification-center-visual-refresh-plan.md)
基线：`1.4.10`，截图取自 2026-11-25 16:50 的 400px 面板（@2x）。

## 1. 现状的问题

同一份真实数据（10 条事件）在现在的面板里长这样：

1. **重复条目占一半**：`右上角全局通知中心设计` 出现 5 次、`Mnemon idle checkpoint review` 出现 3 次。任务每完成一轮就写一条新通知（`task:<sessionId>:<completedAt>`），面板成了事件日志。
2. **一行五重信号**：左侧 3px 色条、未读圆点、整行浅蓝底、加粗标题、hover 的「打开 ›」。它们没有叠加新信息，只叠加注意力。
3. **来源只能读文字**：每行底部一颗「插件：dsh-todo」chip，把行高从 50 抬到 76，一屏只放得下 8 条。
4. **头部 4 个元素、三种权级**：铃铛+标题+未读 chip、任务面板、全部已读、关闭。
5. **来源筛选是原生 select**：视觉重量与分段控件相当，却是个很少用的筛选。

## 2. 目标

- 一屏看完当天的事件：同样 10 条事件，改版后 5 行装下（另有 2 条额外事件也一屏放下）。
- 来源靠图标识别，不占文字行。
- 一个信号只说一件事：颜色只标异常（中断），未读只靠浅底 + 字重。
- 补上应用图标：插件通知显示插件自己的 icon，任务与账号用内置瓦片。

## 3. 行结构

```
[28 图标瓦片]  标题 ....................................... 时间
  ↖ 未读点(右上)   副行：正文 / 结果计数（可选）
  ↖ 状态徽标(右下，仅异常)
```

| 部位 | 规格 |
| --- | --- |
| 行内边距 | `10px 14px`，行间距用 1px 分隔线 |
| 图标瓦片 | `28×28`，圆角 `8`，与文字间距 `12` |
| 标题 | `13.5px`；已读 `500`，未读 `600`，`label-primary` |
| 时间 | `11px`，`label-tertiary`，右对齐、等宽数字 |
| 副行 | `12px`，`label-secondary`，单行省略；异常结果用对应色 |
| 分隔线 | `border-l1`，从 `x=54` 起，不与图标相连 |
| 未读 | 行底 `business 4%` + 标题加粗 + 瓦片右上 `8px` 点（描边取面板底色） |
| 状态徽标 | `11px` 圆，右下 `-2/-2`；仅中断时出现（琥珀/红），完成不上色 |

去掉：3px 色条、「插件：xxx」chip、hover 的「打开 ›」。整行就是按钮，`cursor:pointer` + 悬停底色已经说明可点。

### 3.1 合并重复的任务结果

任务通知的 id 从 `task:<sessionId>:<completedAt>` 改为 `task:<sessionId>:<completed|interrupted>`：

- 同一会话、同一种结果再次发生时，更新 `ts`、`count++`、重新标未读，**不新增行**；
- 状态翻转（完成→中断）落在另一条 id 上，两种结果各自保留最近一次；
- 行上表现：`count > 1` 时副行写「完成 5 次」/「中断 2 次」，单次不写；
- 未读计数按条目算：同一会话连续完成 5 次 = 1 条未读。

语义变化要说清楚：未读单位从「事件」变成「会话结果」。三列看板仍然按会话列任务，所以这层语义和看板一致。

## 4. 应用图标

| 来源 | 图标 |
| --- | --- |
| `task` | 内置瓦片：蓝紫渐变 + 白色 agent 星芒 |
| `account` | 内置瓦片：浅灰底 + 喇叭 |
| `plugin`（能解析到） | 插件自己的 `icon`（data URL） |
| `plugin`（解析不到 / 加载失败） | 内置瓦片：浅灰底 + 拼图 |

**数据来源**：宿主新增只读路由 `GET /task-notifier/api/sources`，从 `pluginManager.listBundles()` / `listPlugins()` 读 `meta.icon`（插件管理器把 icon 读成 base64 data URL）。索引键三个：包名全名、去 scope 的包名（`dsh-todo`）、显示名；命中任一即用。结果缓存 10 分钟，客户端在面板打开时拉一次。

**不改通知契约**：发布方（`dsh-todo` 等）不需要改任何代码。备选方案是给 entry 加 `icon` 字段，需要每个发布方配合，不采用。

**体积**：一个插件图标 1–3KB，20 个 bundle ≈ 40KB，只在面板打开时拉、且 10 分钟缓存，不进 `/state` 轮询。

## 5. 头部与筛选

- 头部只留三件：铃铛 + 「通知」+ 未读 chip；右侧「全部已读」和关闭。任务面板入口下移到底部整宽按钮（工作区已有改动）。
- 分段控件：`全部 / 未读 / 待处理`，计数只在 `> 0` 时显示（不再显示「全部 23」这种无意义的总量）。
- 来源筛选：改成漏斗图标按钮 + 弹出菜单（全部来源 / 任务 / 账号 / 插件，选中项打勾）。按钮只有 28px，不再和分段控件争视觉重量。

## 6. 深色与窄屏

- 深色：瓦片底色在深色下用 `bg-module`，徽标描边取 `bg-layer`；插件图标自带底色，不变。
- 窄屏（< 640px）：面板变全宽 sheet（沿用现有规则），行结构与图标不变。

## 7. 文案

| key | zh | en |
| --- | --- | --- |
| `center.countCompleted` | 完成 {n} 次 | Completed {n}× |
| `center.countInterrupted` | 中断 {n} 次 | Interrupted {n}× |
| `center.sourceMenu` | 来源筛选 | Filter by source |
| `center.icon.task` | 任务结果 | Task result |
| `center.icon.account` | 账号通知 | Account notice |
| `center.icon.plugin` | 插件通知 | Plugin notice |

`center.pluginPrefix`（插件：{name}）保留给系统通知/无障碍标签，不再出现在行内。

## 8. 不做

- 不改三列任务看板。
- 不做「展开合并条目」的二级列表——合并后的行点开就是会话。
- 不引入图标库、不内置任何第三方插件图标。
- 不改插件通知契约（不加 `icon` 字段）。

## 9. 验收

- 同一会话连续完成 5 次：面板 1 行，副行「完成 5 次」，铃铛未读 +1 而不是 +5。
- `dsh-todo` 通知显示它自己的图标；禁用/卸载该插件后降级为拼图瓦片，不出现破图。
- 640px 高的面板至少容纳 9 条单行结果（现在 5 条）。
- 中断行有琥珀/红徽标与「已中断 · 退出」副行；完成行不再上色。
- 深浅色、中英、400/390 窄屏截图各一张，更新 README 与 `docs/design/notification-center/`。
