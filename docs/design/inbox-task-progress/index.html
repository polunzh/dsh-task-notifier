「今天」里混入运行中任务：标题、已运行时长、不确定流动条，父会话下的子代理按树缩进，各自带状态；结果行副行补上「N 个子代理」。不新增区块头，其余行结构、色条、未读规则、筛选与铃铛角标全部保持现状。

垂直成本
一个父会话 + 3 个子代理占 约 138px（父行 62 + 子行 26×3 + 连接线空间）；再加一个独立运行中任务 54px。它们排在「今天」最前，结果区被往下推；640 高的面板里仍留得下 2–3 行结果。

为什么排在今天最前
运行中代表此刻正在发生的事，排在今天通知行前面；如果按开始时间混排，「12 分钟前开始」的活会掉到 8 分钟前的结果后面。它没有已读状态，完成即消失，所以不进未读计数。
02

运行中行 · 行结构

放在「今天」区块最前；父行用色条 + 流动条表达「在跑」，子行只保留状态图标与右侧结果，不再加第二条色条

父会话 + 3 个子代理1 运行 · 1 完成 · 1 中断
父行副行 任务 · 3 个子代理 · 1 运行　子行右侧 已运行 6 分钟 / 完成 / 中断
两个边界形态独立子代理 / 超出 3 子上限
父会话没在跑时，子代理提升为根行，副行写「来自 工作区与插件排序」；第 4 个子代理折成一行跳看板

为什么这样切

父行一条流动条：不确定进度不编百分比，和看板运行中卡片同一条 1.6s 动画；混进今天，不加区块头。
子行不重复状态：图标 = 运行中 / 完成 / 中断，右侧给数字或结论，一行只放一件事。
只展开一层：孙会话不进面板，完整树留给看板；面板宽度只有 400，再深就读不动了。
默认展开前 3 个：不做折叠，第 4 个起折成「还有 N 个」，避免一个组吃掉整屏。
03

结果行的分组标注

只在副行末尾追加「N 个子代理」，不展开子代理的结果；子代理结果仍然只在看板的未读结果列里

① 有分组 · 次数之后
② 无分组 · 保持原样
③ 分组刚收尾 · 运行中行消失，结果落到今天

判断依据是当前任务表里是否还有 parentId === sessionId 的子会话；子会话被裁剪后不再标注，不报错、不补假数据。顺序固定：来源 → 次数 / 正文 → 分组规模。

「待处理」保持现状，只含等待回复 / 审批 / 计划审阅的会话，不把运行中混进来。

计数口径

铃铛角标 = 未读通知 + 等待处理。运行中 +0。
运行中行只按父会话分组；子代理挂在父行下，不单独成行，也不计入未读。
来源筛选：任务 / 全部来源时显示运行中；切到账号或插件时隐藏。
空态：既没有通知、也没有运行中任务时，才显示「暂无通知」。

08

已确认的三件事

2026-11-27 已定，实现按这三条执行

01 · 位置
混进「今天」

不新增区块，运行中行排在今天通知行前面，按父会话分组；「更早」只放历史通知。

02 · 子代理
默认展开前 3 个

不做折叠交互，第 4 个起折成「还有 N 个 ›」，点击进任务面板看完整树。

03 · 角标
运行中不计未读

铃铛角标只统计未读通知与等待处理。运行中靠打开面板后的流动条与时长表达，避免角标长期亮着。
