# 侧栏入口不显示未读数字 · 设计 + 计划

对照图：[before-after.png](./design/sidebar-entry-no-count/before-after.png)（左 1.4.19 带角标 / 右 1.4.20 只留图标）
基线：`1.4.19`（侧栏图标右上角叠 11px 红色数字角标）

## 1. 问题

同一个未读数出现了两次：右上角铃铛有角标，侧栏「任务面板」入口也有角标。两处口径还不一致——侧栏只数「任务未读结果」，右上角铃铛还数账号公告和等你回复的任务，于是常见「铃铛显示 1、侧栏没有数字」，用户看到的是一个入口在报、一个入口在装作没事。

## 2. 方案

侧栏入口只做图标，未读数只出现在右上角铃铛。

```
before                    after
┌──────────────┐          ┌──────────────┐
│ 插件面板      │          │ 插件面板      │
│ ()³ 任务面板 ›│          │ ()  任务面板 ›│
└──────────────┘          └──────────────┘
```

选这个方向的理由：

- 铃铛是所有来源的汇总，侧栏只覆盖任务结果——两个数字并存时，用户得先判断「哪个准」。
- 铃铛已经常驻在会话头，进入不在会话页的界面时它也在；侧栏入口不需要再复制一次信号。
- 侧栏入口的职责是「进任务面板」，数字对它是额外信号，删掉不损失信息。

被否掉的方案：

- **两处口径统一**：可以让侧栏角标等于铃铛总数，但同一个数字在同一屏出现两次，长期仍是噪音；面板入口也不该承担通知计数。
- **侧栏显示「仅任务」的小圆点（无数字）**：仍然是第二个未读信号，换成圆点只是减噪、没解决重复。

## 3. 行为

| 状态 | 结果 |
| --- | --- |
| 有未读 | 侧栏图标不变；右上角铃铛显示总数 |
| 无未读 | 同上 |
| 面板折叠成图标栏（36×36） | 图标居中，不再有贴边角标，和相邻入口同基线 |
| 面板展开成列表 | 图标 18px + 标题，右侧保留「›」 |

`TaskSidebarIcon` 不再订阅 store：图标是静态的，未读数变化不再触发这次重渲染。

## 4. 视觉规格

| 部位 | 规格 |
| --- | --- |
| 图标容器 | `.dtn-panel-mark`：`size × size`（宿主传入，折叠 18 / 列表 16），`inline-flex` 居中，`flex: none` |
| 移除 | `.dtn-panel-mark__badge` 整块（11px 红胶囊、`top:-4 right:-5`、侧栏底色描边） |
| 位置 | 容器不再需要 `position: relative`，图标与同列其它入口保持同一竖直基线 |

## 5. 验证

- `npm test`：`test/client-icon.test.js` 改为断言 `dtn-panel-mark__badge` 不再出现。
- `node scripts/screenshot.mjs`：12 张预览图重新生成，`validateShot` 新增「侧栏图标不得出现未读角标」断言，`panel-light` 侧栏只剩铃铛图标。
- 真机：桌面端侧栏折叠态确认图标无角标、右上角铃铛照常计数；点侧栏入口仍进入三列看板。
